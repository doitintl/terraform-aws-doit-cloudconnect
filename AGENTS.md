# AGENTS.md

Guidance for AI coding agents working in this repository. Human-facing docs are in [README.md](README.md) and [docs/release.md](docs/release.md).

## What this is

A Terraform module that connects a customer's AWS account to DoiT Cloud Intelligence. It creates an IAM role that DoiT assumes with an external ID, attaches policies for the features the customer selects, and registers the account through the `doitintl/doit` provider.

The module is **public and customer-facing**. It is published to the Terraform Registry as `doitintl/doit-cloudconnect/aws`, and customers apply it in their own AWS accounts. Treat it accordingly:

- Inputs, outputs and resource addresses are public API. Renaming a resource without a `moved` block makes Terraform destroy and recreate IAM roles in customer accounts.
- IAM changes grant or revoke access in customer accounts. Keep permissions minimal and explain broad ones in the README, as the Spot Scaling and Attribute sections do.

## Layout

| Path | Contents |
| --- | --- |
| `main.tf` | The DoiT IAM role and trust policy, policy resources and attachments, CloudConnect registration |
| `policies.tf` | Feature name to backend ID mapping, and the policy documents for the core, write and per-feature policies |
| `expert_advice.tf`, `real_time_data.tf`, `spot_scaling.tf` | Resources specific to one feature |
| `variables.tf`, `outputs.tf`, `versions.tf` | Module interface and version constraints |
| `tests/*.tftest.hcl` | `terraform test` suites using mock providers; no credentials needed |
| `examples/` | Runnable examples, rendered on the Registry module page |
| `scripts/dev/` | Developer tooling used locally and in CI, such as the commit message check |
| `scripts/release/` | Release scripts: next version, changelog draft and extraction |
| `scripts/tests/` | Test scripts that complement `terraform test`, and `run-all.sh`, which runs every check |
| `docs/release.md` | Release procedure |

## Before committing

Run every check that CI runs:

```shell
scripts/tests/run-all.sh
```

Add new standalone checks under `scripts/tests/` and call them from `run-all.sh`, so they are part of this one entry point.

If the tools are missing, see "Development" in the README.

## Conventions

- **Commits** follow Conventional Commits (`feat`, `fix`, `chore`, `docs`, `refactor`, `test`, `ci`, ...). The changelog and the next version are derived from commit subjects, so choose the type by its effect on module consumers. Mark breaking changes with `!`.
- **README docs block.** The section between `<!-- BEGIN_TF_DOCS -->` and `<!-- END_TF_DOCS -->` is generated by terraform-docs. Change variable and output descriptions in the `.tf` files, then run `terraform-docs .`.
- **Adding or changing a feature.** Update the feature name mapping in `policies.tf` and the `additional_features` validation in `variables.tf` together. Add tests to `tests/features.tftest.hcl`. Update the README feature table and the "Managed policy quota" section if the number of attached policies changes.
- **Policy parity.** IAM policies must match DoiT's CloudFormation member template. Intentional differences are listed as exceptions in `scripts/tests/check_policy_parity.py`; any other difference fails the check.
- **Pinning.** GitHub Actions are pinned to commit SHAs, and pre-commit hooks to commit SHAs with a version comment. Keep it that way when adding or updating them.
- **Version constraints.** `versions.tf` declares the minimum supported Terraform and provider versions, and CI validates the module on the minimum Terraform version. Raising a minimum is a breaking change.

## Releases

Pushing a `vX.Y.Z` tag publishes that version to the Registry immediately. Published tags must never be moved or deleted. Don't create or push tags unless asked. Follow [docs/release.md](docs/release.md), which also requires a `CHANGELOG.md` entry for every tag.
